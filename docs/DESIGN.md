# otoium 設計メモ（60点版 → 100点版）

## 60点版（単純な実装）に足りないもの
1. 無音/RMS 分割だけ → 連続音で崩れる、子音と母音の境界が出ない
2. ファイル名=音素と決め打ち → 録音ミス・台本違いを検出できない
3. 1 WAV = 1 エイリアス → VCV で必須の複数エイリアスが出せない
4. 失敗時も oto.ini を出力 → 壊れた設定が混入
5. 固定パラメータ → 話者・録音環境に適応できない
6. 閉鎖+破裂など音素内部構造・ポーズの扱いがない
7. 境界の確信度がなく、曖昧でも断定する
8. 台本形式が固定（8mora 以外に対応できない）

## 100点版で実装したこと
| 不足点 | 対応 |
|---|---|
| 1 | 音響特徴+セミマルコフ Viterbi による強制アライメント |
| 2 | 台本無しフリーデコーダで独立認識し照合（母音一致率・子音確認・母音核数） |
| 3 | モーラ列ごとに VCV/CV/VC を生成 |
| 4 | FAIL/ERROR/REVIEW は oto.ini に出さず review/report へ |
| 5 | 全ファイルでの Viterbi 再学習 (MAP) で話者適応、モデル保存/再利用 |
| 6 | 破裂=閉鎖+バースト、破擦=閉鎖+摩擦、拗音=+半母音、ん=鼻音核 |
| 7 | 境界ごとに確信度（尤度コントラスト/境界証拠）を算出、低いものは保留 |
| 8 | かな・カタカナ・ローマ字、拗音/外来音、台本ファイル指定 |

## 既知の限界
* 合成音声で検証済みだが、実録音ではしきい値（`Config.thr_*`, `*_agree`）の調整が必要な場合がある。
* 停止音の「先頭の閉鎖」は無音と区別できないため、先頭モーラの子音開始は推定（バースト位置が確実）。
* 鼻音どうし（ん→な）の境界は音響的に曖昧で、誤差が大きくなりうる。
* 深層学習モデルは使わない（自己教師あり GAUSSIAN 音響モデル）。将来 `AcousticModel.loglik` を
  差し替えるだけで、ニューラル音響モデルを組み込める設計。


## v1.1 追加
* 自動調整 (tune.py): 検証スコアを目的関数に座標降下。
* 救済 (pipeline._final): 5種のパラメータ変更 + 末尾モーラ削減仮説。
* 微調整 (refine.py): 1ms 精度。合成音声で母音開始の平均誤差 3.0ms → 0.9ms。
* 特徴量: DC除去、ノイズフロア正規化、Δ特徴、キャッシュ、並列読込。
* 出力: TextGrid、既存 oto.ini とのマージ、接頭辞/接尾辞。

## v1.2
* `_んん` 等の「ん」のみのファイル: 母音核の代わりに鼻音核で判定し、同一音の境界は推定位置として扱う。
* しきい値の自動校正 (calibrate.py)。
* MLP フレーム分類器 (mlp.py) をガウスモデルに併用 (重みは自動調整)。
* 録音ごとの適応。整列にのみ使い、独立検証は適応前モデルで行う (自己確認の防止)。
* 救済・自動調整から検証側パラメータを除外 (検証の甘化を防ぐ)。

## v1.3
* 精度モード ultra / custom。回数は個別に指定可能 (config.resolve)。
* NN のアンサンブル、音素ごとの時間長分布の学習、発話速度比による適応、高信頼ファイルのみでの再学習。
* 末尾モーラ削減の救済に、残音・母音の引き延ばし・母音内の谷の検査を追加 (正常な録音を誤って短縮しない)。
